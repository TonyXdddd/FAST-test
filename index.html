Enter в Input: как работает эмуляция неявной отправки формы

Сверху — цепочка по этапам: что происходит от нажатия Enter до отправки формы. Ниже — 20 живых кейсов. Кликните в поле и нажмите настоящий Enter: справа журнал покажет каждый шаг. Кнопка «Симулировать» шлёт синтетические keydown → keypress. Нативного change при этом не будет, это умеет только настоящее нажатие.

Зачем вообще эмулировать

  • Внутренний <input> лежит в shadow DOM компонента. С формой снаружи он не связан, поэтому браузер сам по Enter ничего не отправит.
  • Браузерный алгоритм учитывает только нативные элементы. Наших полей и наших кнопок для него не существует.
  • Поэтому Input сам повторяет алгоритм неявной отправки из спецификации HTML (§4.10.22.2) и учитывает всех соседей в форме — и нативных, и кастомных.

Цепочка по этапам

  1. браузер keydown

    FAST вызывает handleKeydownEvent. Enter здесь не обрабатываем и возвращаем true. Если вернуть что-то другое, FAST сам вызовет preventDefault(), и браузер не пришлёт keypress (кейс 17).

    public handleKeydownEvent($event: KeyboardEvent): boolean {
  // Enter здесь не обрабатываем
  return true;
}

  2. браузер keypress → компонент handleKeypressEvent

    Браузер присылает keypress, только если keydown никто не отменил и не идёт IME-ввод. Поэтому отмена на keydown снаружи (кейс 14) выключает всю цепочку, и отдельная проверка не нужна.

    // input.template.ts
@keypress="${(x, c) => x.handleKeypressEvent(c.event as KeyboardEvent)}"

// input.ts
public handleKeypressEvent($event: KeyboardEvent): boolean {
  handleFormEnterKeypress($event, this.elementInternals);
  return true; // иначе FAST вызовет preventDefault и пропадёт change
}

  3. наш код фильтр клавиши и отложенный запуск

    Нужен именно Enter, без IME (isComposing, keyCode 229 в Safari) и без Ctrl/Alt/Meta (кейс 20). Отправку не делаем сразу, а откладываем через setTimeout. Наш обработчик висит на внутреннем input и срабатывает первым, раньше обработчиков на хосте, форме и документе.

    const isEnter = $event.key === 'Enter'
  && !$event.isComposing && $event.keyCode !== 229
  && !$event.ctrlKey && !$event.altKey && !$event.metaKey;
if (!isEnter) {
  return;
}
setTimeout(() => { /* этап 5 */ });

  4. браузер действие по умолчанию для keypress: change

    Когда keypress обработан, браузер фиксирует значение: если текст менялся, внутренний input шлёт change, а handleInputChangeEvent пробрасывает его наружу. Это происходит до нашего setTimeout, поэтому change приходит раньше отправки, как у нативного поля (кейс 1).

  5. наш код setTimeout: проверка отмены

    К этому моменту событие прошло весь путь. Если кто-то вызвал preventDefault() (например, на форме, кейс 15), выходим. Иначе запускаем сам алгоритм.

    setTimeout(() => {
  if (!$event.defaultPrevented) {
    mimicFormEnterBehavior($elementInternals);
  }
});

  6. шаг 1 есть ли форма

    elementInternals.form. Если формы нет, выходим (кейс 19). Атрибут form="id" на самом компоненте тоже работает: это делает ElementInternals.

  7. шаг 2 кнопка по умолчанию

    Это первая submit-кнопка в form.elements — по порядку документа, включая элементы вне формы с form="id" (кейс 7). Submit-кнопками считаются:

    • <button> без type или с type="submit";
    • input[type=submit] и input[type=image];
    • наш компонент с isSubmitButton = true.

    Checkbox с checked кнопкой не считается (кейс 11). input[type=image] в form.elements нет, его ищем отдельно.

    function isSubmitButton($element: Element): boolean {
  if ($element instanceof HTMLButtonElement) return $element.type === 'submit';
  if ($element instanceof HTMLInputElement) return $element.type === 'submit' || $element.type === 'image';
  return ($element as Participant).isSubmitButton === true;
}

  8. шаг 3 кнопка нашлась

    Если кнопка неактивна (:disabled, в том числе через <fieldset disabled>), ничего не делаем и следующую кнопку не ищем (кейсы 8, 9). Если активна — button.click(). Видимость роли не играет (кейс 10).

    if (!button.matches(':disabled')) {
  button.click();
}
return;

  9. браузер после click()

    click() даёт такой же клик, как мышь: он всплывает и его можно отменить (кейс 13). Если клик не отменён, браузер проверяет форму: при ошибке — invalid и фокус на поле, отправки нет (кейс 16). Если всё в порядке — событие submit (его тоже можно отменить) и отправка. Наша кнопка в обработчике клика вызывает form.requestSubmit(), дальше происходит то же самое.

  10. шаги 4–5 кнопок нет: подсчёт полей

    Считаем текстовые поля формы: нативные input 12 типов (text, search, url, tel, email, password, date, month, week, time, datetime-local, number) и наши компоненты с blocksImplicitSubmission = true. Checkbox, select, textarea и hidden не считаются. Если полей меньше двух — form.requestSubmit(), submitter = null (кейсы 2, 5, 12). Иначе ничего не делаем (кейсы 3, 4).

    if (Array.from(form.elements).filter(isSubmitBlocking).length < 2) {
  form.requestSubmit();
}
